# Plan: TypeScript `ModUiClient` (pedalboard scope)

Status: approved, 2026-10-07.

## Context
The backend contract is now documented in `openapi.yml`. The next step is a typed, documented,
class-based browser client that wraps it with `fetch` + the main WebSocket, so new UI code (and AI
tools) can drive mod-ui without hand-written `$.ajax` calls. First iteration covers **pedalboards only**:
list, info, load (awaiting the WebSocket `loading_end`) and load default. TypeScript is added with
minimal footprint: a self-contained folder; the build emits one **unversioned**
`html/js/lib/modui-client.js` that the page loads via a `<script>` tag.

Target usage (from the request):
```ts
const client = new ModUiClient();
const device = client.device;
const pedalboards: PedalboardReference[] = await client.pedalboards.list();
const pedalboard: PedalboardInfo = await pedalboards[0].info();
await device.load(pedalboard);   // resolves only after WS "loading_end"
await device.loadDefault();      // bundlepath inferred from the list
```

## Key backend facts the design relies on
- `GET /pedalboard/list` → `PedalboardSummary[]`; the default pedalboard has `bundle` ending in
  `/default.pedalboard` and `title: "Default"` (`mod/webserver.py` PedalboardList).
- `GET /pedalboard/info/?bundlepath=` → `PedalboardInfo` **without** the bundle path → the client adds `bundlepath`.
- `POST /pedalboard/load_bundle/` (form: `bundlepath`, `isDefault`) does **not** clear the current graph;
  the frontend always calls `GET /reset` first (`html/js/desktop.js` `loadPedalboard` / `reset`). The client does the same.
- `host.load()` is synchronous: `loading_start … loading_end <snapshotId>` are pushed on the WebSocket
  **before** the HTTP response → the waiter must be registered before the POST.
- A freshly opened WebSocket receives a full state replay ending in `loading_end` → the client's
  `connect()` resolves only after that first `loading_end`, so it can't be mistaken for the load's.
- An owned socket must answer `ping`→`pong` and `data_ready N`→`data_ready N` (flow control, `mod/session.py`).

## `modui-client.ts` design
Build: `esbuild modui-client.ts --bundle --format=iife --target=es2018 --outfile=../modui-client.js`
(no minify, readable). End of file assigns `window.ModUiClient` (and the error classes) when `window` exists;
named `export`s keep it importable by tests / future ESM consumers.

- **`ModUiClientOptions`**: `baseUrl` (default `location.origin`; ws URL derived http→ws / https→wss),
  `fetch` and `WebSocket` implementations (injectable, defaults to globals), `webSocket` (reuse an existing
  socket, e.g. the page's `ws` from `host.js` – then the client never answers `ping`/`data_ready` nor closes it),
  `loadTimeoutMs` (default 60 000).
- **`ModUiHttpError`** (status, url, body) and **`ModUiTimeoutError`**; `ModUiError` base.
- **`HttpTransport`** (internal): `getJson(path, query)`, `postForm(path, form)`; `cache: 'no-store'`; non-2xx → `ModUiHttpError`.
- **`EventChannel`** (internal, exposed as `client.events` with `on(command, handler)` returning an unsubscribe fn):
  lazy connect, parses `"<cmd> <args>"`, auto-replies `pong`/`data_ready` when owned, `ready` promise resolved on
  first `loading_end`, `waitFor(cmd, predicate, timeoutMs)`, `close()`.
- **`PedalboardReference`** (class built from a list entry): readonly `bundlepath`, `title`, `uri`, `broken`,
  `factory`, `hasTrialPlugins`, `version`, getter `isDefault`; `info(): Promise<PedalboardInfo>`.
- **`PedalboardInfo`** (interface): server fields typed per `openapi.yml` + `bundlepath`.
- **`PedalboardsApi`** (`client.pedalboards`): `list(): Promise<PedalboardReference[]>`.
- **`Device`** (`client.device`):
  - `load(target: PedalboardInfo | PedalboardReference | string, opts?)` → await `events.ready`; `GET /reset`
    (false → error); register `loading_end` waiter; `POST /pedalboard/load_bundle/`; `ok:false` → cancel waiter and throw;
    resolve with `{ name, snapshotId }` after `loading_end`. Calls are serialized (internal promise chain).
  - `loadDefault(opts?)` → finds the list entry whose bundle ends in `/default.pedalboard`, loads with `isDefault=1`;
    throws `ModUiError` if absent.
  - `reset()` → `GET /reset` (public; used by `load`).
- `ModUiClient`: `device`, `pedalboards`, `events`, `connect()`, `close()`.

Documentation style: file header explaining architecture/flow; TSDoc on every public symbol with
`@example`, the HTTP/WS calls it makes, and links to the matching `openapi.yml` operationId.

## Tests (`modui-client.test.ts`, vitest, node env)
`FakeWebSocket` (open/emit/sent log) + `vi.fn` fetch returning canned JSON. Cases:
list → references; `info()` URL-encodes `bundlepath` and adds it; `load()` order is reset → load_bundle with
correct form body and resolves only after `loading_end` (not on the replay one); `ok:false` rejects; timeout rejects
(fake timers); string/reference/info targets accepted; `loadDefault` sends `isDefault=1`, throws when not found;
owned socket replies `pong`/`data_ready`, shared socket doesn't; non-2xx → `ModUiHttpError`.
`npm test` = `tsc --noEmit && vitest run`.

## Known limitation (documented)
When the client loads a pedalboard while the classic UI is open, the canvas updates via WebSocket, but the
desktop title/bundle state (set only from the HTTP response in `desktop.loadPedalboard`) does not. Fix later
with a backend broadcast (suggestion below).
